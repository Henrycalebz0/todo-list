# Project instructions

Use this file as the working guide when changing this todo list app.

## App structure

- `server.js` — Node.js HTTP server, REST API routes, request validation, JSON persistence, and static file delivery.
- `public/index.html` — page structure and accessible labels.
- `public/styles.css` — presentation and responsive layout.
- `public/app.js` — browser behavior and calls to the REST API.
- `todos.json` — local runtime data. This file is generated by the app and must stay out of Git.
- `README.md` — local setup and app overview.
- `FLOWGRAPH.md` — user and API flow.
- `ENDPOINT_TESTS.md` — API endpoint behavior to verify.
- `DEPLOY.md` — live Railway setup and persistent storage notes.

Keep browser code in `public/` and server code in `server.js`. If the server grows enough that routing, storage, and static-file handling become hard to maintain in one file, split those responsibilities into modules under `src/` and update `package.json` and this guide at the same time.

## API contract

- `GET /api/todos` returns the todo array.
- `POST /api/todos` accepts a non-empty `title` and creates an incomplete todo.
- `PATCH /api/todos/:id` updates a non-empty `title`, a boolean `completed`, or both.
- `DELETE /api/todos/:id` removes a todo.
- Return JSON errors with suitable HTTP status codes for invalid input, missing todos, unknown routes, and unsupported methods.
- Keep the API behavior documented in `ENDPOINT_TESTS.md` in sync with any route changes.

## Data and deployment

- Keep persistence behind the server; browser code must use the API rather than reading the data file.
- Use `RAILWAY_VOLUME_MOUNT_PATH` when Railway provides it, then `DATA_DIR`, and otherwise the project directory for local development.
- Do not commit `todos.json`, secrets, credentials, or deployment tokens.
- Preserve the existing JSON todo shape (`id`, `title`, `completed`, `createdAt`) unless a deliberate migration is added.
- Keep `PORT` environment-variable support so the server works locally and on Railway.
- Update `DEPLOY.md` if the hosting service, storage mount path, or deployment workflow changes.

## Implementation conventions

- Use Node.js built-in modules unless a dependency is needed and explained.
- Validate request data on the server even when the browser form already validates it.
- Render todo titles as text; do not insert user-provided content with `innerHTML`.
- Preserve accessible labels, visible focus styles, keyboard operation, and responsive behavior.
- Keep changes small and update the relevant documentation when behavior or project structure changes.
